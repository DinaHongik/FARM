# Controlled binding evaluation: 8192-token direct-output rerun

Frozen before inference: 150 constructed requests in 50 families; 60 ingredient-binding, 30 static-value, 30 mixed, and 30 deliberately missing-information cases. Correct endpoint pairs are supplied. References are known by construction from explicit request templates, without model judgments. No per-case human annotation is claimed. See PLAN.md for reviewer mapping and the design rationale.

The selected 20 triggers and 8 actions come from the archived FARM catalog and official endpoint documentation. All evaluated input fields have text controls. Static values, including numeric-looking text, remain strings; this benchmark does not measure numeric/boolean coercion. All trigger ingredients use the documented string runtime representation, while original semantic type labels are retained. Unknown account options and unsupported field controls are outside the selected scope. Primitive schema validity does not establish every service-specific constraint or platform readiness.

The three workflows use the prior configuration implementation unchanged: strong unified agent with checker-assisted review, FARM with validation/repair, and FARM without feedback/repair. FARM arms share identical initial drafts. Use Ollama Cloud deepseek-v4-flash:0731, thinking disabled, temperature 0, inference seed 9052026, at most 7 calls per case/arm and 8192 generated tokens per call. Actual usage is reported. No training, post-outcome prompt tuning, hidden-reference feedback, account lookup, or live platform calls occur.

A separate evaluator compares exact field-source/value decisions with frozen references and interprets bindings over three hidden event fixtures for each of 120 fully specified requests (360 fixture events). One fixture changes distractors while preserving bound sources; another changes bound sources while preserving distractors. Static-only fixtures test invariance. No fixture output or reference enters generation or repair. These are simulated argument-materialization checks, not real IFTTT execution.

Primary metric is whole-configuration decision correctness over all 150 requests. Missing-input decisions can be correct but never count as fully bound actions. Supporting metrics are field accuracy, ingredient binding P/R/F1 and exact set match, static-value accuracy, required-field coverage/correct coverage, declared-schema validity, missing-input handling, simulated argument-materialization pass rate over the 120 fully specified cases, and repair rescues/regressions. All metrics include numerators and denominators. Empty binding sets do not inflate F1; spurious predicted edges count as false positives. Malformed/failed model outputs remain failures in applicable denominators.

Bootstrap paired differences by request family (50 clusters, 10000 resamples). Variants and repeated events are correlated, not extra independent cases. Report category and error breakdowns, actual calls/tokens/provider latency, and infrastructure failures separately. Cache identity and artifact hashes must match on resume. Smoke tests use four separate request families excluded from the benchmark. Keep the original real-request experiment and AI-assisted annotation outputs untouched.

The primary executable scorer is evaluate.py. It does not import FARM's checker. The scorer's reference helper is for local mutation tests only, and cannot be imported by the cloud workflow runner. Deliberately wrong ingredients, literals, fields, future-trigger dependencies, omissions, fabricated sources, and malformed configurations must fail those tests before launch. Fixed generator and scorer hashes are included in the run identity. Never label an outcome as real-platform execution or full natural-language generalization.

## Runtime correction and smoke calibration

This rerun follows the completed 2048-token experiment, where 181 malformed terminal outputs all ended at the token limit. All 150 requests, references, four disjoint smoke cases, workflow prompts, checker, scorer, model, seed, and seven-call ceiling are retained. Two runtime settings change: output limit 2048 to 8192; separate model thinking from low to disabled. Explicit planner/verifier/repair agent calls remain unchanged. This is not a budget-only ablation, and the 150 requests are not a newly untouched sample.

Increasing the budget with thinking enabled was insufficient in separate smoke-only diagnostics. At 8192, one of 26 unique calls truncated; at 16384, one of 24 truncated. Both had 12 valid terminal draft shapes but failed the stricter call-completion gate. At 32768, truncation also recurred; that diagnostic was stopped before full generation. A probe changed only the thinking flag on a saved 32768-token failed request; it returned parseable verifier JSON in 115 tokens with no thinking content. Those artifacts are preserved. These changes were chosen from transport/completion observations, not semantic accuracy.

Before full generation, all smoke calls must finish without token-limit termination, be nonempty parseable JSON, and use thinking disabled; all 12 terminal drafts must have valid protocol shape. The API must emit no thinking content. Smoke semantic correctness is not a launch criterion. Failure pauses the supervisor before the 150-case run. Exact request replay is mandatory. During the full run, limits and prompts remain frozen; failures are retained in denominators and completion metrics are reported separately. There are no extra per-case budget retries, dropped cases, or post-hoc output repairs. JSON/CSV/TeX aggregates are saved without generating PDFs or modifying manuscripts.

Provider documentation checked during diagnosis: https://docs.ollama.com/capabilities/thinking and https://ollama.com/library/deepseek-v4-flash%3A0731-cloud . The live same-request probe confirms this model accepts the disabled mode through the configured Ollama Cloud API.
